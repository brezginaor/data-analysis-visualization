# Исследование и подготовка данных SOC

## Исходные данные

Для анализа используется `iavd_incidents_raw_target.parquet` — выгрузка карточек инцидентов информационной безопасности. В ней **240 295 записей и 97 полей**. Даты создания карточек охватывают период с **12 апреля 2024 года по 3 сентября 2025 года** (UTC). Для первоначальной проверки структуры использовалась выборка `iavd_1000_incidents_raw_target.parquet` на 1 000 записей; выводы о полноте полей сделаны по основному файлу.

Цель подготовки данных — обеспечить единый способ загрузки для аналитических расчётов и дашборда на Taipy. Результаты исследования сохранены в `notebooks/01_eda.ipynb`, код загрузки — в `src/data_loader.py`.

## Структура и полнота данных

Поле `EntityId` уникально: повторяющихся идентификаторов в полном наборе нет. Это позволяет использовать его для подсчёта карточек, в том числе при анализе полей с несколькими значениями.

Часть специализированных полей заполнена редко. Например, в `Ошибки` есть только **13** непустых значений, в `Типы угроз` — **653**, в `Эскалировался на L2?` — **1 756**. По одной лишь доле пропусков нельзя определить, связано ли это с качеством выгрузки или с тем, что соответствующий признак применим только к отдельным инцидентам. Поэтому поля не удаляются, а пропуски не заменяются автоматически нулями или `False`: такая замена могла бы придать отсутствующим сведениям конкретный смысл.

Среди основных категориальных полей обнаружены следующие особенности:

| Поле | Результат и значение для анализа |
|---|---|
| `Вердикт` | 7 категорий, пропусков нет. **150 675 карточек (62,7%)** имеют вердикт `False Positive`. Категория `Не указан` присутствует в самих данных; её нельзя приравнивать к подтверждённому инциденту. |
| `Критичность` | 5 категорий. Чаще всего встречается `Средняя` — **158 159 карточек**. Для графиков уровни нужно сортировать по значимости, а не по алфавиту. |
| `Тип инцидента` | 99 непустых категорий и **116 пропусков**. Для отображения пропусков добавлено отдельное поле, исходное не изменяется. |
| `Источник инцидента` | 5 непустых вариантов и **5 пропусков**. Встречаются записи с двумя источниками. |
| `Фаза реагирования` | 9 вариантов; ровно `Закрыт` указано у **239 557 карточек**. Встречаются и сочетания нескольких фаз. |

Некоторые значения объединены разделителем `~~||~~`, например `Ankey SIEM NG~~||~~MaxPatrol SIEM`. Если развернуть такие ячейки в отдельные строки, одна карточка будет учитываться несколько раз. Поэтому в основной таблице многозначные поля оставлены без изменений. При построении графиков по отдельным источникам или фазам понадобится отдельный расчёт с контролем уникальных `EntityId`.

## Проверка временных полей

Для оценки возможности расчёта длительности сопоставлены `Создан` и `Дата закрытия (факт)`.

| Результат сравнения | Карточек |
|---|---:|
| Дата закрытия отсутствует | 42 139 |
| Закрытие раньше создания | 12 331 |
| Разница дат неотрицательная | 185 825 |

Все отрицательные интервалы по модулю меньше **261 секунды**. Это небольшое расхождение, но его причина по имеющимся данным не установлена. Менять исходные даты или считать отрицательное время равным нулю было бы необоснованно. Вместо этого такие случаи помечаются отдельным признаком и исключаются только из расчёта неотрицательной длительности.

Медиана разницы между созданием и закрытием для оставшихся **185 825 карточек** — **0,2054 часа (около 12,3 минуты)**. Этот показатель отражает лишь разницу двух временных отметок; использовать его как подтверждённое время работы аналитика или MTTR нельзя без проверки значения полей.

В выгрузке также есть два разных столбца: `Время решения` и `Время Решения`. Их значения нельзя считать однородными длительностями. В первом столбце **19 845** крупных чисел при интерпретации как Unix-времени в миллисекундах дают даты периода выгрузки; во втором **195 948** крупных чисел аналогично интерпретируются как временные метки в микросекундах. Это указывает на возможное смешение форматов или назначения полей, но не устанавливает его причину. До уточнения семантики эти столбцы **не используются для KPI времени решения**.

## Что реализовано в загрузчике

Функция `load_incidents(path)` читает Parquet, проверяет наличие обязательных полей (`EntityId`, `Создан`, `Дата закрытия (факт)`, `Тип инцидента`), отсутствие пустых и повторяющихся `EntityId`, затем добавляет три признака:

| Поле | Назначение |
|---|---|
| `invalid_duration` | `True`, если дата закрытия раньше даты создания. |
| `duration_hours` | Разница дат в часах; для отрицательных интервалов и отсутствующей даты закрытия — `NaN`. |
| `incident_type_display` | Копия типа инцидента, в которой пропуски заменены на `Не указан` для отображения. |

Исходные поля и строки сохраняются. На полном файле функция возвращает DataFrame размером **240 295 × 100**. Результаты проверены запуском в ноутбуке; автоматизированные тесты пока не добавлены.

```python
from src.data_loader import load_incidents

df = load_incidents("data/iavd_incidents_raw_target.parquet")
```
