# Карточки SOC: отчёт к дашборду (задание 1)

Данные: `iavd_incidents_raw_target.parquet` (Полный набор · 12.04.2024 — 03.09.2025). Фильтры по умолчанию: весь период, все дни, все уровни критичности. Собран `report.py` 20.11.2026.

## 1. Из чего состоит поток карточек и как он менялся?

*Столбчатая диаграмма с накоплением по неделям, цвет — вердикт аналитика.*

- За 510 дн. поступило **240 295** карточек — ≈ 471 в день. Самая нагруженная неделя — с 10.06.2024: 21 642 карточки.
- **62,7 %** карточек закрыты как False Positive, реальных инцидентов — **28 606** (11,9 %), дубликаты и прочие — 2,6 %, без вердикта — **22,8 %**.
- Карточки без вердикта занижают и долю FP, и долю реальных инцидентов: по ним неизвестно, чем закончился разбор.

## 2. Какие правила корреляции создают больше всего шума?

*Линейчатая диаграмма с накоплением: 10 правил с наибольшим числом карточек, цвет — вердикт.*

- 10 правил из 361 дают **34,2 %** всех карточек. Лидер — `GL_FW_S04_Host_Port_Scan`: 10,0 % потока, из них 92,3 % без вердикта и 6,4 % False Positive.
- У **2** из 10 правил доля карточек с вердиктом «Решён» составляет менее 1 %. На эти правила приходится **12,1 %** потока: `GL_FW_S04_Host_Port_Scan` (0,2 % — решён, 92,3 % — без вердикта), `GL_AUTH_S12_Login_After_Prolonged_Inactivity` (0,2 % — решён, 35,0 % — без вердикта). Низкая доля подтверждённых инцидентов может быть связана с неполнотой разметки. Эти правила требуют дополнительного анализа.
- Самое «полезное» правило топа — `Nad_Possible_Scan_Activity`: 37,2 % его карточек — реальные инциденты.

## 3. Берут ли критические карточки в работу быстрее остальных?

*Кривые накопленной доли (ECDF) по уровням критичности, логарифмическая шкала времени.*

- **Нет.** Медиана времени до взятия в работу у критических карточек — **42,9 мин**, у остальных — 4,8 мин: критические ждут в 8,9 раза дольше. По карточкам с корректными временными данными наблюдается более длительное ожидание у критических карточек.
- Медианы по уровням: критическая — 42,9 мин; высокая — 3,9 мин; средняя — 4,4 мин; низкая — 14,4 мин; отсутствует — 4,3 мин.
- У 81 407 карточек (33,9 %) отсутствует дата взятия в работу или временной интервал некорректен. Определить время реакции для таких карточек невозможно, поэтому они исключены из расчёта. Кривые построены по 158 888 карточкам.

## 4. Когда SOC не укладывается в SLA взятия в работу?

*Тепловая карта: тип дня (по производственному календарю) × трёхчасовое окно суток, цвет — доля нарушений.*

- Норматив взятия в работу нарушен у **34,2 %** карточек (54 276 из 158 858 с известной датой взятия).
- Хуже всего — пятница, 9–12 ч по Москве: **43 %** карточек взяты позже норматива (7 513 карточек в окне); лучшее окно — 15 %. Худшее и лучшее окна выбираются среди ячеек, где не меньше 100 карточек: в остальных доля случайна.
- Рабочие дни — 35,2 % нарушений, выходные и праздники — 25,3 %.

## Оговорки

- Время до взятия в работу = `Дата взятия в работу` − `Создан`. Поля `Время решения` и `Время Решения` не используются: их единицы неоднородны (см. `docs/data_report.md`).
- Отрицательные интервалы (взятие раньше создания) считаются ошибкой данных и исключаются, а не обнуляются.
- Нарушение SLA = интервал больше `SLA по взятию в работу Атаки` (норматив в миллисекундах). Карточки без даты взятия или без норматива в эту долю не входят.
- Время суток и даты — по Москве; тип дня — из `calendar.parquet`, для дат вне календаря — по дню недели.
- «Реальный инцидент» — вердикт «Решён», «Без вердикта» — «Не указан», «Дубликат и прочие» — остальные вердикты.
