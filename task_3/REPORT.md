# Почему модель решила так: SHAP-объяснение для SOC (задание 3)

Модель курса `lgbm_gate1__v001`, рабочий порог 0,0193: оценка не ниже порога — карточка идёт в приоритет. Разложение TreeSHAP: вклады 73 признаков в логарифме шансов для 8 карточек команды SHAP № 4 (сентябрь 2025). Собран `report.py` 21.11.2026.

Уровни показа выбраны так: **одна карточка** — водопад решения; **поток** — средние вклады и их знак по исходам; **сомнения** — контрфактическая проверка вкладов обогащения. Объяснение описывает модель, а не причину инцидента.

## Коротко для SOC

- **Объяснение арифметически согласовано:** sigmoid(база + 73 вкладов) воспроизводит оценку модели с точностью 5·10⁻⁷ — это округление вероятности в файле. Вклады сходятся с решением.
- **Крупнейшие средние вклады в группе:** «freq_Наименование», «Команда», «Создан», «Алерт» (см. раздел 3).
- **Объяснение подтверждается данными:** Карточка 523997: модель подняла её с оценкой 0,2915, и даже без признаков обогащения оценка осталась бы выше порога — решение держат данные самой карточки (главный толчок «к инциденту» — «Команда» с вкладом +2,02 лог. шанса). Классификация согласуется с меткой TP; для проверки смысла вкладов нужен контекст событий карточки.
- **Объяснение выглядит сомнительно:** Карточка 523235 — ложная тревога с оценкой 0,0277, на волоске от порога 0,0193. Уберём вклады обогащения (Алерт, Вендор из сием, len_Значение Инцидента (группировка): 1,08 лог. шанса) — оценка падает до 0,0096, ниже порога. Модель подняла карточку в основном потому, что заполнено обогащение, а не потому, что в карточке есть сигнал атаки: с сентября это поле деградировало.
- **На выбранных карточках группы:** при исключении вкладов обогащения из суммы условная оценка оказалась бы ниже порога 2 из 4 поднятых карточек (50 %), в том числе 2 ложных тревог из 2 поднятых.

## 1. Уровень карточки: почему модель решила так?

*Водопад: базовая линия → крупнейшие вклады → итог; proba = sigmoid(итог). Пример — карточка 523235 команды 4.*

- Базовая линия (средний логарифм шансов по обучению): -8,85.
- «Алерт»: +1,07 лог. шанса
- «categoryHigh»: +0,99 лог. шанса
- «create_lag_s»: +0,97 лог. шанса
- «Команда»: +0,92 лог. шанса
- «Создан»: -0,48 лог. шанса
- «src_is_private»: -0,39 лог. шанса
- «event_age_days»: +0,38 лог. шанса
- «cmd_entropy»: +0,35 лог. шанса
- «остальные 65 признаков»: +1,47 лог. шанса
- Итог: sigmoid(итог) = 0,0277 → поднята в приоритет; истина — не инцидент.

Решение складывается из всех вкладов, включая положительные, отрицательные и «остальные». SHAP описывает поведение модели, а не причину события.

## 2. Можно ли объяснению верить? Проверяемость

*Проверка воспроизводимости: оценка модели из одних вкладов.*

- Из base и 73 вкладов восстановлена оценка каждой карточки: максимальное расхождение с proba из файла — 5·10⁻⁷, то есть ровно округление вероятности до 6 знаков.
- Значит, показанные вклады действительно те, по которым модель приняла решение, а не пересчёт постфактум другой моделью.

## Что предлагаем

1. Показывать аналитику водопад вкладов рядом с решением модели — по образцу дашборда `task_3/`.
2. Не доверять поднятиям, которые держатся на обогащении, пока заполнение «Алерт»/«Вендор» не восстановлено: это ровно те карточки, где объяснение нельзя проверить данными карточки.
3. Следить за долей «обогащением поднятых» карточек во времени: её рост — сигнал деградации входов, а не поломка модели.
4. Помнить: SHAP объясняет модель, а не причину инцидента; «Hostname атакующего» в объяснении — не доказательство атаки.
