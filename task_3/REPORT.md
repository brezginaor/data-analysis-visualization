# Почему модель решила так: SHAP-объяснение для SOC (задание 3)

Модель курса `lgbm_gate1__v001`, рабочий порог 0,0193: оценка не ниже порога — карточка идёт в приоритет. Разложение TreeSHAP: вклады 73 признаков в логарифме шансов для 320 карточек сентября 2025 (40 команд × 8 карточек: по 2 исхода TP/FP/FN/TN). Собран `report.py` 20.11.2026.

Уровни показа выбраны так: **одна карточка** — водопад решения; **поток** — средние вклады и их знак по исходам; **сомнения** — контрфактическая проверка вкладов обогащения. Объяснение описывает модель, а не причину инцидента.

## Коротко для SOC

- **Объяснению можно верить арифметически:** sigmoid(база + 73 вклада) воспроизводит оценку модели с точностью 5·10⁻⁷ — это округление вероятности в файле. Вклады сходятся с решением.
- **Модель держится на адресах и частотах:** топ опоры — «Hostname атакующего», «Hostname Цели», `src_is_private`, `freq_Наименование` (см. раздел 3).
- **Объяснение подтверждается данными:** Карточка 523983: модель подняла её с оценкой 0,9973, и даже без признаков обогащения оценка осталась бы выше порога — решение держат данные самой карточки (главный толчок «к инциденту» — «Hostname атакующего» с вкладом +5,05 лог. шанса). Это объяснение подтверждается исходом: карточка действительно решена как инцидент.
- **Объяснение выглядит сомнительно:** Карточка 528063 — ложная тревога с оценкой 0,0427, на волоске от порога 0,0193. Уберём вклады обогащения (Алерт, Вендор из сием, len_Значение Инцидента (группировка): 1,30 лог. шанса) — оценка падает до 0,012, ниже порога. Модель подняла карточку в основном потому, что заполнено обогащение, а не потому, что в карточке есть сигнал атаки: с сентября это поле деградировало.
- **Сомнение носит системный характер:** без вкладов обогащения упали бы ниже порога 16 из 160 поднятых карточек (10 %), в том числе 14 ложных тревог из 80 поднятых.

## 1. Уровень карточки: почему модель решила так?

*Водопад: базовая линия → крупнейшие вклады → итог; proba = sigmoid(итог). Пример — сомнительная карточка 528063.*

- Базовая линия (средний логарифм шансов по обучению): -8,85.
- «Команда»: +0,79 лог. шанса
- «Создан»: +0,78 лог. шанса
- «len_Значение Инцидента (группировка)»: +0,68 лог. шанса
- «Алерт»: +0,59 лог. шанса
- «dst»: +0,50 лог. шанса
- «cmd_chars»: +0,44 лог. шанса
- «src_is_private»: -0,35 лог. шанса
- «cmd_entropy»: +0,35 лог. шанса
- «остальные 65 признаков»: +1,97 лог. шанса
- Итог: sigmoid(итог) = 0,0427 → поднята в приоритет; истина — не инцидент.

Вклады по модулю не складываются «в пользу» решения: «src_is_private» толкает к инциденту, а «Hostname атакующего» здесь — против. Решение — баланс 73 вкладов, а не один флаг.

## 2. Можно ли объяснению верить? Проверяемость

*Проверка воспроизводимости: оценка модели из одних вкладов.*

- Из base и 73 вкладов восстановлена оценка каждой карточки: максимальное расхождение с proba из файла — 5·10⁻⁷, то есть ровно округление вероятности до 6 знаков.
- Значит, показанные вклады действительно те, по которым модель приняла решение, а не пересчёт постфактум другой моделью.

## 4. Один признак — в обе стороны: средние вклады по исходам

*Средний подписанный SHAP топ-признаков для TP/FP/FN/TN.*

- **Hostname Цели**: TP +1.63 · FP +0.83 · FN -0.21 · TN -0.21
- **Hostname атакующего**: TP +1.75 · FP +1.05 · FN +0.01 · TN -0.45
- **dst**: TP +0.71 · FP +0.76 · FN +0.03 · TN -0.05
- **freq_Наименование**: TP +1.21 · FP +0.71 · FN -0.13 · TN -0.20
- **src_is_private**: TP +1.05 · FP +0.50 · FN -0.18 · TN -0.37

Главный вывод для SOC: признаки вроде «Hostname атакующего» сильно работают у найденных инцидентов (TP +1,75), почти ничего не дают у пропущенных (FN +0,01) и умеренно у ложных тревог (FP +1,05). Модель опирается на то, кто и куда стучался, — когда адресного сигнала нет, она теряет опору и откладывает карточку: именно так выглядят её пропуски.

## 5. Сомнительные объяснения: деградировавшее обогащение

*Контрфактическая проверка: убираем вклады «Алерт», «Вендор из сием», «len_Значение Инцидента» и пересчитываем оценку.*

- Без обогащения упали бы ниже порога 16 из 160 поднятых карточек — 10 %.
- Среди поднятых ложных тревог у порога (оценка до 0,1) таких 14 из 80 — их поднятие почти целиком сделано «сломанным» полем.
- Карточка 528063 — ложная тревога с оценкой 0,0427, на волоске от порога 0,0193. Уберём вклады обогащения (Алерт, Вендор из сием, len_Значение Инцидента (группировка): 1,30 лог. шанса) — оценка падает до 0,012, ниже порога. Модель подняла карточку в основном потому, что заполнено обогащение, а не потому, что в карточке есть сигнал атаки: с сентября это поле деградировало.

## Что предлагаем

1. Показывать аналитику водопад вкладов рядом с решением модели — по образцу дашборда `task_3/`.
2. Не доверять поднятиям, которые держатся на обогащении, пока заполнение «Алерт»/«Вендор» не восстановлено: это ровно те карточки, где объяснение нельзя проверить данными карточки.
3. Следить за долей «обогащением поднятых» карточек во времени: её рост — сигнал деградации входов, а не поломка модели.
4. Помнить: SHAP объясняет модель, а не причину инцидента; «Hostname атакующего» в объяснении — не доказательство атаки.
