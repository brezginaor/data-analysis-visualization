Уровни показа выбраны так: **одна карточка** — водопад решения; **группа из 8 карточек** — средние вклады и их знак по исходам; **сомнения** — условный пересчёт выбранных SHAP-вкладов. Объяснение описывает модель, а не причину инцидента.

## Коротко для SOC

- **Восстановление вероятности:** sigmoid(база + 73 вкладов) согласуется с округлённой `proba` из файла: максимальная разница 5·10⁻⁷.
- **Проверка аддитивности в логарифмах шансов:** отдельный `raw_score` в предоставленных CSV отсутствует. Независимую сверку `base + ΣSHAP` с `raw_score` при допуске 10⁻⁶ провести нельзя.
- **Крупнейшие средние вклады в группе:** «freq_Наименование», «Команда», «Создан», «Алерт» (см. раздел 3).
- **Пример корректно классифицированной тревоги (TP):** Карточка 523997: модель подняла её с оценкой 0,2915, а при арифметическом исключении выбранных SHAP-вкладов условная оценка остаётся выше порога. Наибольший положительный вклад даёт «Команда» (+2,02 лог. шанса). Исход TP подтверждает правильность классификации этой карточки, но не смысл SHAP-объяснения: исходные значения признаков и контекст события в этом анализе не проверялись.
- **Объяснение выглядит сомнительно:** Карточка 523235 — ложная тревога с оценкой 0,0277, при рабочем пороге 0,0193. Если арифметически исключить SHAP-вклады выбранных признаков (Алерт, Вендор из сием, len_Значение Инцидента (группировка): сумма 1,08 лог. шанса), условная оценка составит 0,0096 — ниже порога. Эти вклады требуют проверки по исходным данным; это не новый прогноз модели и не доказательство ухудшения качества обогащения.
- **На выбранных карточках группы:** после арифметического исключения выбранных SHAP-вкладов условная оценка оказалась бы ниже порога у 2 из 4 поднятых карточек (50 %). Это не результат повторного запуска модели.

## 1. Уровень карточки: почему модель решила так?

*Водопад: базовая линия → крупнейшие вклады → итог; proba = sigmoid(итог). Пример — карточка 523235 команды 4.*

- Базовое значение SHAP (логарифм шансов): -8,85.
- «Алерт»: +1,07 лог. шанса
- «categoryHigh»: +0,99 лог. шанса
- «create_lag_s»: +0,97 лог. шанса
- «Команда»: +0,92 лог. шанса
- «Создан»: -0,48 лог. шанса
- «src_is_private»: -0,39 лог. шанса
- «event_age_days»: +0,38 лог. шанса
- «cmd_entropy»: +0,35 лог. шанса
- «остальные 65 признаков»: +1,47 лог. шанса
- Итог: sigmoid(итог) = 0,0277 → поднята в приоритет; истина — не инцидент.

Решение складывается из всех вкладов, включая положительные, отрицательные и «остальные». SHAP описывает поведение модели, а не причину события.

## 2. Можно ли объяснению верить? Проверяемость

*Раздельно проверяем аддитивность в логарифмах шансов и согласованность вероятности.*

- **Проверка аддитивности в логарифмах шансов:** отдельный `raw_score` в предоставленных CSV отсутствует. Независимую сверку `base + ΣSHAP` с `raw_score` при допуске 10⁻⁶ провести нельзя.
- Восстановление вероятности из `base + ΣSHAP`: максимальное расхождение с округлённой `proba` — 5·10⁻⁷ (допуск 6·10⁻⁷).
- Совпадение округлённой вероятности подтверждает согласованность чисел в файлах, но не заменяет независимую проверку исходного выхода модели.
