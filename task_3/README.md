# Задание 3. SHAP-объяснение решений модели

Интерактивный дашборд Taipy показывает, как SHAP-вклады влияют на оценку модели `lgbm_gate1__v001` при пороге 0,0193. Анализ ограничен восемью карточками команды № 4.

Выводы с числами — в [`REPORT.md`](REPORT.md): его собирает `report.py` из тех же функций, что и плитки.

## Визуализации

| № | Вопрос | Представление |
|---|---|---|
| 1 | **Почему модель решила так по этой карточке?** | Горизонтальный водопад от базового значения до итоговой оценки. |
| 2 | **Какие признаки дают наибольшие вклады в нашей группе?** | Десять признаков с наибольшим средним модулем SHAP. |
| 3 | **Куда толкает признак у инцидентов, а куда у ложных тревог?** | Средние SHAP-вклады со знаком по категориям TP, FP, FN и TN. |
| 4 | **Почему модель подняла ложную тревогу?** | Сравнение исходной оценки FP-карточки и условного пересчёта SHAP с порогом модели. |

**Проверяемость:** KPI «Объяснение сходится с оценкой» сравнивает `sigmoid(base + ΣSHAP)` с округлённой `proba`. Независимая проверка аддитивности по `raw_score` возможна только при наличии этого поля.

**Примеры для разбора:** корректная тревога TP и ложная тревога FP. Для FP условно пересчитываем оценку, арифметически исключая SHAP-вклады «Алерт», «Вендор из сием», «len_Значение Инцидента (группировка)». Результат — повод проверить исходные значения признаков, а не доказательство причины ошибки.

**Показатели:** оценка выбранной карточки, согласованность SHAP с оценкой модели, главный признак группы по среднему |SHAP| и доля условных оценок ниже порога.

**Цвета вкладов:** оранжевый — увеличение оценки инцидента, серый — уменьшение; тёмно-красный выделяет ложную тревогу.

**Выборка:** только команда SHAP № 4 (8 карточек). Фильтры — исходы (TP/FP/FN/TN) и выбор карточки для водопада. Другие команды не показываются, фильтры действуют на все графики.

## Запуск

Требуются Python 3.12 и Poetry. Данные находятся в репозитории: `data/task3/cards_practice.csv` и `data/task3/shap_cards.csv`.

Из корня репозитория:

```bash
poetry install
poetry run python task_3/app.py
```

Приложение доступно по адресу http://127.0.0.1:5014.

Сформировать отчёт и запустить тесты:

```bash
poetry run python task_3/report.py
poetry run python -m unittest discover -s task_3
```

## Решения по данным

- **Используются предрассчитанные вклады** из `data/task3/shap_cards.csv`. Совпадение с округлённой `proba` проверяется с допуском 6·10⁻⁷. Если предоставлен исходный `raw_score`, дополнительно проверяется `|base + ΣSHAP − raw_score| ≤ 10⁻⁶`. Восстанавливать `raw_score` из округлённой `proba` для такой точной проверки некорректно.
- **Порог 0,0193 — часть модели**, не меняется; фильтры не влияют на решение, только на показ.
- **Условный пересчёт SHAP**: из суммы вкладов арифметически исключены «Алерт»/«Вендор из сием»/«len_Значение Инцидента (группировка)». Полученная оценка показывает чувствительность разложения к этим вкладам, но не является новым прогнозом модели. Чтобы оценить эффект реального удаления признаков, необходим отдельный прогон (ablation). Деградация обогащения по этим данным не установлена.
- **Поднятые карточки** = proba ≥ 0,0193 (флаг «инцидент» в `cards_practice.csv`); исходы TP/FP/FN/TN согласованы с `y_true` и порогом (проверяется в `loader.py`).
- **Вклады — в логарифме шансов**: положительные толкают «к инциденту», отрицательные «к легитимному»; итог водопада = ln(p/(1−p)) оценки.
- Объяснение ≠ причинность: SHAP описывает поведение модели, а не физику инцидента.
- Все результаты рассчитаны только для восьми карточек команды № 4.
