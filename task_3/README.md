# Решение задания 3 · Почему модель решила так: SHAP-объяснение для SOC

Дашборд Taipy для работников SOC: объяснение решений модели `lgbm_gate1__v001` (порог 0,0193) через SHAP-вклады — понятное и **проверяемое**. Вклады TreeSHAP показаны на трёх уровнях: одна карточка (водопад решения), группа из 8 карточек (средние вклады и их знак по исходам), сомнительные объяснения (условный пересчёт SHAP-вкладов).

Выводы с числами — в [`REPORT.md`](REPORT.md): его собирает `report.py` из тех же функций, что и плитки.

## Четыре вопроса и почему выбран именно этот график

| # | Вопрос работника SOC | График | Почему именно он |
|---|---|---|---|
| 1 | **Почему модель решила так по этой карточке?** | Горизонтальный водопад: базовая линия → крупнейшие вклады → итог (лог. шансы) | Вклады последовательно складываются; положительный сдвигает оценку вправо, отрицательный — влево. Итог переводится в вероятность через sigmoid. |
| 2 | **Какие признаки дают наибольшие вклады в нашей группе?** | Линейчатая топ-10 по среднему \|SHAP\| | Показывает признаки с крупнейшими по модулю вкладами среди 8 карточек команды № 4; это не статистика всего потока SOC. |
| 3 | **Куда толкает признак у инцидентов, а куда у ложных тревог?** | Сгруппированные столбцы среднего подписанного SHAP-вклада по TP/FP/FN/TN | Показывает направление вкладов в каждой категории. Среднее около нуля может скрывать компенсацию положительных и отрицательных вкладов. |
| 4 | **Почему модель подняла ложную тревогу?** | Сравнение исходной оценки карточки FP и условной оценки после исключения трёх SHAP-вкладов; порог модели | Две полосы и порог позволяют увидеть чувствительность арифметического объяснения. Отдельная подпись показывает ID разбираемой FP-карточки; выбор карточки для водопада не меняет четвёртый график (фильтр исходов учитывается). Вторая оценка не получена повторным запуском модели. |

**Проверяемость:** KPI «Объяснение сходится с оценкой» сравнивает `sigmoid(base + ΣSHAP)` с округлённой `proba`. Независимая проверка аддитивности по `raw_score` возможна только при наличии этого поля.

**Примеры для разбора:** корректная тревога TP и ложная тревога FP. Для FP условно пересчитываем оценку, арифметически исключая SHAP-вклады «Алерт», «Вендор из сием», «len_Значение Инцидента (группировка)». Результат — повод проверить исходные значения признаков, а не доказательство причины ошибки.

Примеры TP и FP для нашей команды 4 выбираются автоматически из её карточек при генерации `REPORT.md`.
Они не обязательно совпадают с примерами, подобранными по всем 320 карточкам.
Результаты относятся к 8 карточкам группы, а не ко всему потоку SOC.

**KPI-плитки:** оценка выбранной карточки и решение, сходимость вкладов с оценкой, главный признак группы по среднему |SHAP|, доля поднятых карточек, для которых условная оценка оказалась ниже порога после арифметического исключения выбранных SHAP-вкладов (не реальный эффект удаления признаков).

**Цвета — как в заданиях 1 и 2:** оранжевый — «к инциденту», серый — «к легитимному», тёмно-красный — сомнительные поднятия.

**Выборка:** только команда SHAP № 4 (8 карточек). Фильтры — исходы (TP/FP/FN/TN) и выбор карточки для водопада. Другие команды не показываются, фильтры действуют на все графики.

## Запуск

Нужны Python 3.12 и Poetry; зависимости те же, что для заданий 1–2. Из корня репозитория:

```bash
poetry install
```

Для запуска используются только два файла из учебного набора, **они включены в репозиторий**:


Они считываются автоматически. Распаковывать `IAVD_3.7_ML_team.zip` и переносить файлы вручную не нужно. Остальные учебные данные по-прежнему не включаются в Git.

```bash
poetry run python task_3/app.py
```

Откройте http://127.0.0.1:5014. Отчёт:

```bash
poetry run python task_3/report.py
```


## Решения по данным

- **Используются предрассчитанные вклады из `course_pack`** (`shap_cards.csv`). Совпадение с округлённой `proba` проверяется с допуском 6·10⁻⁷. Если предоставлен исходный `raw_score`, дополнительно проверяется `|base + ΣSHAP − raw_score| ≤ 10⁻⁶`. Восстанавливать `raw_score` из округлённой `proba` для такой точной проверки некорректно.
- **Порог 0,0193 — часть модели**, не меняется; фильтры не влияют на решение, только на показ.
- **Условный пересчёт SHAP**: из суммы вкладов арифметически исключены «Алерт»/«Вендор из сием»/«len_Значение Инцидента (группировка)». Полученная оценка показывает чувствительность разложения к этим вкладам, но не является новым прогнозом модели. Чтобы оценить эффект реального удаления признаков, необходим отдельный прогон (ablation). Деградация обогащения по этим данным не установлена.
- **Поднятые карточки** = proba ≥ 0,0193 (флаг «инцидент» в `cards_practice.csv`); исходы TP/FP/FN/TN согласованы с `y_true` и порогом (проверяется в `loader.py`).
- **Вклады — в логарифме шансов**: положительные толкают «к инциденту», отрицательные «к легитимному»; итог водопада = ln(p/(1−p)) оценки.
- Объяснение ≠ причинность: SHAP описывает поведение модели, а не физику инцидента.
- Набор проекта — команда SHAP № 4; при запуске и генерации отчёта отбираются только её 8 карточек. После обновления кода выполните `poetry run python task_3/report.py` для пересчёта `REPORT.md` на группе 4.
