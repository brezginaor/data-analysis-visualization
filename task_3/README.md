# Решение задания 3 · Почему модель решила так: SHAP-объяснение для SOC

Дашборд Taipy для работников SOC: объяснение решений модели `lgbm_gate1__v001` (порог 0,0193) через SHAP-вклады — понятное и **проверяемое**. Вклады TreeSHAP показаны на трёх уровнях: одна карточка (водопад решения), поток (средние вклады и их знак по исходам), сомнительные объяснения (контрфактическая проверка обогащения).

Выводы с числами — в [`REPORT.md`](REPORT.md): его собирает `report.py` из тех же функций, что и плитки.

## Четыре вопроса и почему выбран именно этот график

| # | Вопрос работника SOC | График | Почему именно он |
|---|---|---|---|
| 1 | **Почему модель решила так по этой карточке?** | Водопад: базовая линия → крупнейшие вклады → итог (лог. шансы) | SHAP-вклады складываются, а не соревнуются: водопад показывает, из чего сложилась оценка, включая «против» — виден баланс 73 признаков, а не один флаг. Итог пересчитывается в оценку через sigmoid прямо в подписи. |
| 2 | **Можно ли объяснению верить?** | Плитка-проверка: sigmoid(база + вклады) против proba из файла | Проверяемость — требование задания. Расхождение 5·10⁻⁷ = округление вероятности до 6 знаков: показаны те самые вклады, по которым модель решала. |
| 3 | **На чём модель держится и куда толкает признак?** | Линейчатая топ-10 по среднему \|SHAP\| + сгруппированные столбцы среднего подписанного вклада по TP/FP/FN/TN | Средний модуль отвечает «на чём держится», знак по исходам — «в какую сторону». Сгруппированные столбцы ставят исходы рядом: видно, что «Hostname атакующего» у найденных инцидентов +1,75, а у пропущенных +0,01 — модель теряет опору, когда адресного сигнала нет. |
| 4 | **Где объяснение выглядит сомнительно?** | Точечная диаграмма: оценка модели (лог. шкала) против вклада «Алерт» | Признак обогащения деградировал с сентября, и его вклад — кандидат в «ложные причины». Лог. шкала по вертикали нужна, чтобы одновременно видеть карточки у порога (0,0193) и уверенные 0,99. |

**Обязательные случаи из условия найдены контрфактической проверкой** (убираем вклады «Алерт», «Вендор из сием», «len_Значение Инцидента» и пересчитываем оценку):

Примеры TP и FP для нашей команды 4 выбираются автоматически из её карточек при генерации `REPORT.md`.
Они не обязательно совпадают с примерами, подобранными по всем 320 карточкам.
Результаты относятся к 8 карточкам группы, а не ко всему потоку SOC.

**KPI-плитки:** оценка выбранной карточки и решение, сходимость вкладов с оценкой, главная опора потока, доля «держащихся на обогащении» поднятий.

**Цвета — как в заданиях 1 и 2:** оранжевый — «к инциденту», серый — «к легитимному», тёмно-красный — сомнительные поднятия.

**Выборка:** только команда SHAP № 4 (8 карточек). Фильтры — исходы (TP/FP/FN/TN) и выбор карточки для водопада. Другие команды не показываются, фильтры действуют на все графики.

## Запуск

Нужны Python 3.12 и Poetry; зависимости те же, что для заданий 1–2. Из корня репозитория:

```bash
poetry install
```

Для запуска используются только два файла из учебного набора, **они включены в репозиторий**:

```text
data/task3/cards_practice.csv
data/task3/shap_cards.csv
```

Они считываются автоматически. Распаковывать `IAVD_3.7_ML_team.zip` и переносить файлы вручную не нужно. Остальные учебные данные по-прежнему не включаются в Git.

```bash
poetry run python task_3/app.py
```

Откройте http://127.0.0.1:5014. Отчёт:

```bash
poetry run python task_3/report.py
```

Проверки расчётов (без данных и без Taipy):

```bash
poetry run python -m unittest discover -s task_3
```

## Решения по данным

- **Используются предрассчитанные вклады из `course_pack`** (`shap_cards.csv`), как рекомендует методичка курса: «SHAP-значения предрассчитаны». Пересчёт на лету не нужен — вклады проверены на сходимость с оценкой.
- **Порог 0,0193 — часть модели**, не меняется; фильтры не влияют на решение, только на показ.
- **«Держится на обогащении»** = контрфакт: без вкладов «Алерт»/«Вендор из сием»/«len_Значение Инцидента» оценка упала бы ниже порога. Это не переобучение модели, а честный способ показать, какие поднятия не объясняются данными карточки.
- **Поднятые карточки** = proba ≥ 0,0193 (флаг «инцидент» в `cards_practice.csv`); исходы TP/FP/FN/TN согласованы с `y_true` и порогом (проверяется в `loader.py`).
- **Вклады — в логарифме шансов**: положительные толкают «к инциденту», отрицательные «к легитимному»; итог водопада = ln(p/(1−p)) оценки.
- Объяснение ≠ причинность: SHAP описывает поведение модели, а не физику инцидента.
- Набор проекта — команда SHAP № 4; при запуске и генерации отчёта отбираются только её 8 карточек. После обновления кода выполните `poetry run python task_3/report.py` для пересчёта `REPORT.md` на группе 4.

## Условие задания 3

У нас есть решение модели и разложение этого решения по вкладам. Нужно сделать объяснение **понятным и проверяемым**: показать вклады для одной карточки, группы похожих карточек или всего потока; выводы — понятные работникам SOC; найти хотя бы один случай, где объяснение подтверждается данными, и хотя бы один, где оно выглядит сомнительно.
