# Можно ли доверять модели-советнику SOC: отчёт к дашборду (задание 2)

Модель `wlarf-dec-jun-v3`, порог 0,18: оценка ≥ 0,18 — «инцидент», карточка идёт в приоритет. Лог модели: сентябрь 2025 — ноябрь 2025, 15 839 карточек с вердиктом («Решён» — реальный инцидент, «False Positive» — ложное срабатывание); ещё 3 554 оценок без такого вердикта в метрики не входят. Собран `report.py` 18.11.2026.

## Коротко для руководителя SOC

- **Модель пропускает каждый 5-й реальный инцидент:** 335 из 1 666 (20,1 %, 95 % интервал 18,3 %–22,1 %) ушли в отложенные.
- **Очередь она разгружает сильно:** откладывает 75,4 % карточек. Но из поднятых ею карточек инцидентом оказывается только 34,2 % — каждая 3-я.
- **Ошибки систематические:** в категориях «Управление учётными записями» (47 из 50), «Подозрительная активность» (63 из 98), «Вредоносное ПО» (28 из 89) модель пропускает инциденты намного чаще среднего.
- **Уровню риска «низкий» верить нельзя:** в нём 38,1 % всех реальных инцидентов, в том числе все пропуски. Порог 0,18 лежит внутри «низкого» уровня (до 0,37), поэтому 1 659 карточек с «низким» риском модель сама же подняла в приоритет.
- **Поток изменился:** доля реальных инцидентов 6,3 % в предполагаемом окне обучения и 10,7 % в период работы модели; «Вендор из сием» заполнен у 50 % и 43 % карточек.
- **Вывод:** как сортировке очереди модели можно доверять — верх очереди она собирает хорошо. Как фильтру, который откладывает карточки без проверки, — нельзя.

## 1. Сколько реальных инцидентов модель пропускает и меняется ли это со временем?

*Точки по неделям с 95 % интервалом и линией среднего.*

- Всего пропущено 335 из 1 666 реальных инцидентов — **20,1 %**.
- По месяцам: сентябрь 2025 — 32,6 % (95 из 291); октябрь 2025 — 20,1 % (154 из 768); ноябрь 2025 — 14,2 % (86 из 607).
- Интервалы недель широкие: в неделе от 57 до 363 инцидентов, поэтому скачок одной недели ещё не поломка, а тренд нужно читать по нескольким неделям подряд.

## 2. Что даёт SOC разбор очереди в порядке модели?

*Кривая поиска (cumulative gains) с отметкой рабочего порога.*

- На пороге 0,18 модель поднимает **25 %** очереди и находит в них **80 %** реальных инцидентов; без модели в той же доле очереди было бы 25 % инцидентов.
- Чтобы найти 90 % инцидентов, по оценке модели нужно разобрать 50 % очереди.

## 3. Где модель «слепа»?

*Точечная диаграмма: доля пропусков по категориям IRP с 95 % интервалами.*

- «Управление учётными записями»: пропущено 47 из 50 (94 %, интервал 84 %–98 %) — **систематически выше среднего**.
- «Подозрительная активность»: пропущено 63 из 98 (64 %, интервал 54 %–73 %) — **систематически выше среднего**.
- «Вредоносное ПО»: пропущено 28 из 89 (31 %, интервал 23 %–42 %) — **систематически выше среднего**.
- «Атака на инфраструктуру»: пропущено 34 из 204 (17 %, интервал 12 %–22 %).
- «Сетевая безопасность»: пропущено 139 из 1 009 (14 %, интервал 12 %–16 %).
- «Инцидент»: пропущено 19 из 211 (9 %, интервал 6 %–14 %).

Систематическая зона — та, где весь интервал лежит правее средней доли пропусков: там ошибки не объясняются случайностью.

## 4. Можно ли верить уровню риска модели?

*Линейчатая диаграмма: доля реальных инцидентов на каждом уровне риска.*

- Низкий, оценка < 0,18 — модель отложила: инцидентом оказались 3 % карточек (335 из 11 945; 20 % всех инцидентов).
- Низкий, оценка 0,18–0,37 — модель подняла: инцидентом оказались 18 % карточек (299 из 1 659; 18 % всех инцидентов).
- Средний (0,37–0,63): инцидентом оказались 30 % карточек (406 из 1 361; 24 % всех инцидентов).
- Высокий (0,63–0,80): инцидентом оказались 56 % карточек (250 из 446; 15 % всех инцидентов).
- Критический (от 0,80): инцидентом оказались 88 % карточек (376 из 428; 23 % всех инцидентов).

Высоким уровням риска верить можно: на «критическом» инцидентом оказываются 88 % карточек. «Низкий» уровень смешивает отложенные карточки и карточки, которые модель подняла в приоритет: шкалу риска и порог решения нужно согласовать, иначе аналитик видит «низкий риск» у карточки из приоритета.

## 5. Изменился ли поток карточек с тех пор, как модель обучали?

*Линии по месяцам основного датасета курса: доля реальных инцидентов и заполненность «Вендора».*

- Окно обучения неизвестно; по названию версии `wlarf-dec-jun-v3` считаем им декабрь 2024 — июнь 2025.
- Доля реальных инцидентов среди карточек с вердиктом: 6,3 % тогда и 10,7 % в период работы модели.
- «Вендор из сием» (обогащение карточки) заполнен у 50 % карточек тогда и у 43 % в период работы; по месяцам работы — всё реже.
- Модель работает на потоке, который заметно отличается от того, на котором её, вероятно, учили: это довод за переобучение на свежих месяцах.

## Что предлагаем

1. Использовать модель для порядка разбора, а не как фильтр: отложенные карточки всё равно просматривать.
2. Карточки из категорий-«слепых зон» разбирать без учёта оценки модели.
3. Согласовать шкалу риска с порогом решения: «низкий» не должен включать карточки из приоритета.
4. Переобучить модель на свежих месяцах и вернуть заполнение обогащения («Вендор из сием»).

## Оговорки

- Метрики считаются только по вердиктам «Решён» и «False Positive»; спам, дубликаты и оценки без карточки не входят.
- Пропуск — реальный инцидент с оценкой ниже 0,18. В жизни его всё равно разобрал аналитик: это то, что SOC потерял бы, если бы доверял модели без проверки.
- 95 % интервалы — интервалы Уилсона для доли.
- Даты и недели — по Москве.
